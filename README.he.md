# משו״ב — אינטגרציה ל־Home Assistant באמצעות HACS

אינטגרציה קהילתית ולא רשמית למשו״ב. בחרו איזה מידע להביא ל־Home Assistant לכל חשבון ומוסד.

הפרויקט אינו קשור לחברת משו״ב. [הערות גרסה](RELEASE_NOTES.md) · [יומן שינויים](CHANGELOG.md) · [הנחיות תרומה](CONTRIBUTING.md)

## התקנה

נדרש **Home Assistant 2025.3 ומעלה**.

**HACS:** פתחו **HACS → Integrations → ⋯ → Custom repositories**, הוסיפו `https://github.com/NirBY/ha-mashov` בקטגוריית **Integration**, התקינו את Mashov והפעילו מחדש.

**התקנה ידנית:** העתיקו את `custom_components/mashov` אל `/config/custom_components/mashov` והפעילו מחדש.

לעדכון, התקינו דרך HACS והפעילו מחדש. בחירת המידע, התזמונים, מזהי הישויות וההתאמות הקיימות נשמרים; מידע חדש אינו מופעל אוטומטית.

## הגדרה

1. פתחו **הגדרות → מכשירים ושירותים → הוספת אינטגרציה → Mashov**.
2. הזינו משתמש וסיסמה ובחרו מוסד. הקלדה מסננת את רשימת המוסדות; כשהרשימה אינה זמינה, הזינו שם או סמל מוסד בשדה החלופי.
3. בחרו **סוגי מידע לשליפה**, הגדירו **תזמוני רענון** לפי הצורך ולחצו **שליחה**. חשבון חדש מתחיל ללא בחירה; בחירה ריקה מתחברת לחשבון אך אינה יוצרת חיישני מידע.

כל שילוב חשבון ומוסד הוא hub נפרד. עדכון פרטי כניסה חל על ה־hub שנבחר בלבד. שנת הלימודים מתקדמת ב־1 בספטמבר, אלא אם הוגדרה שנה קבועה; אפשר להפעיל **שנת לימודים אוטומטית** כדי לחזור להתקדמות אוטומטית.

אפשר להגדיר את התזמון המשותף ב־`configuration.yaml` ולהפעיל מחדש:

```yaml
mashov:
  schedule_type: daily
  schedule_time: "14:00"
  schedule_days: [0, 2, 4] # שני, רביעי, שישי — לתזמון שבועי
  schedule_interval: 60   # דקות — לתזמון במרווח קבוע
```

YAML גובר על התזמון המשותף בטופס; תזמונים נפרדים לתלמיד ולסוג מידע נשארים עצמאיים. בסיס ה־API, בחירת המידע, חלון התאריכים ומגבלת הרשומות מוגדרים באפשרויות. השדה הישן `schedule_day` עדיין נתמך.

[תמונות של טפסי ההקמה וההגדרה הנוכחיים](docs/configuration.md)

## תכונות

- **18 סוגי מידע לבחירה**, עם תמיכה בכמה חשבונות ותלמידים ללא ערבוב נתונים.
- **תזמון כללי ותזמון לכל סוג מידע לכל תלמיד**, בתוך טופס ההקמה וההגדרה; שליחה אחת שומרת את כל הטיוטות.
- **תור רענון משותף** לכל החשבונות, לרבות רענון ידני ומתוזמן; רענון ממוקד שומר את נתוני יתר התלמידים וחותמות הזמן שלהם.
- **חיישנים ולוח חופשות**, עם רשומות, סיכומים, זמני עדכון ומצב זמינות או מידע ישן.
- **תיבת דואר לפי חשבון**, עם ספירת שיחות וכותרות; תוכן מלא דורש הסכמה נפרדת, ללא הורדת קבצים מצורפים.
- **שמירת מטמון וסשן**, ניסיונות חוזרים, שנת לימודים אוטומטית וניקוי תלמידים שעזבו לאחר אימות רשימה עדכנית.
- **ממשק בעברית, אנגלית, ערבית, רוסית ואוקראינית**, כולל עריכת תזמונים מימין לשמאל בעברית ובערבית.
- **דשבורד משו״ב לייב, כרטיסי Lovelace ושלושה blueprints** להקראה, תזכורת תיק והודעות לוח מודעות.
- **פעולות ודיאגנוסטיקה:** רענון, עדכון אפשרויות, יצירת דשבורד למנהלים ודיווח שגיאות פנימיות לאחר בדיקת המשתמש.

## אפשרויות

פתחו **הגדרות → מכשירים ושירותים → Mashov → Configure** ליד החשבון הרצוי. הטופס מחולק לנתונים, תזמון, חשבון והגדרות מתקדמות. התזמונים הנוכחיים והעזרה סגורים כברירת מחדל.

| הגדרה | ברירת מחדל / התנהגות |
| ---: | ---: |
| חלון שיעורי בית | 7 ימים אחורה ו־21 קדימה; חלון בקשה ולא מחיקת היסטוריה |
| תזמון משותף | יומי ב־14:00, לפי אזור הזמן של Home Assistant |
| שיחות דואר אחרונות | 20, בטווח 1–50 |
| רשומות במאפייני חיישן | 100, בטווח 10–500; ייתכן צמצום נוסף לפי מגבלת גודל |
| בסיס API | `https://web.mashov.info/api/` |
| שנת לימודים אוטומטית | פעילה אלא אם החשבון מוגדר לשנה קבועה |

### תזמוני רענון

בחרו תלמיד ואז **כללי** או סוג מידע. בטלו את סימון הירושה כדי להגדיר תזמון אישי: שעה ביומי, שעה וימים בשבועי, דקות במרווח קבוע (5–1440). המעבר בין תלמידים וסוגים שומר טיוטות; **שליחה** שומרת את כולם יחד. ביטול אינו משנה את ההגדרות השמורות.

בהקמה מגדירים תחילה ברירות מחדל; התלמידים זמינים לאחר ההתחברות ושליפת הרשימה. התזמונים מזוהים לפי מזהה תלמיד קבוע. תלמיד חדש יורש את ברירות המחדל, וחופשות ותיבת דואר נשארות ברמת המוסד והחשבון. לעריכתן בחרו **מידע משותף לחשבון ולבית הספר וברירות מחדל**.

**התזמונים הנוכחיים** מציגים את כל הקטגוריות והזמנים בפועל. מידע כבוי אינו נשלף. רענונים ממתינים בתור אחד; טעינה מחדש של hub ממתינה רק לבקשה הפעילה שלו ומדלגת על בקשותיו שבתור. רענון ידני מעדכן את כל המידע שנבחר. שליפה בלילה עלולה לגרום להודעות פעילות ממשו״ב; הגדירו שעות יום אם הדבר מפריע.

[תמונות של העורך בתוך הטופס](docs/configuration.md) · [דוגמאות פעולות לתזמון](docs/services.md#mashovset_options)

### סוגי מידע לשליפה / Data to fetch

זמין ב־**v1.1.0**. חשבון חדש מתחיל ללא בחירה; בשדרוג הבחירה נשמרת.

| קבוצה | סוגי מידע |
| ---: | ---: |
| שיעורים | שיעורי בית, תכנון שבועי, מערכת שעות, היסטוריית שיעורים |
| ציונים | ציונים, ציונים תקופתיים, תעודות |
| התנהגות | התנהגות, התנהגות יומית, התנהגות מחוץ לשיעור, הערות מעקב |
| רשומות תלמיד | חומרי לימוד, קובצי תלמיד, בקשות להצדקת היעדרות, שעות פרטניות |
| בית הספר | לוח מודעות, חופשות ולוח שנה |
| תיבת דואר | מספר שיחות שלא נקראו וכותרות אחרונות; תוכן מלא הוא אפשרות נפרדת |

הבחירה חלה על כל התלמידים בחשבון. תיבת הדואר שייכת לחשבון וחופשות לבית הספר. זמינות תלויה בהרשאות המוסד. קבצים מוצגים כרשומות ואינם מורדים; האינטגרציה אינה מגישה טפסים או בקשות לבית הספר.

### בחירה וביטול נתונים

הוסיפו קטגוריות מהרשימה או הסירו תגיות באמצעות **×**, ולחצו **שליחה**. שינוי בחירה טוען מחדש את החשבון ומנסה לרענן מיד. לדשבורד בסיסי בחרו שיעורי בית, התנהגות, תכנון שבועי, מערכת שעות, היסטוריית שיעורים וציונים; הוסיפו חופשות עבור לוח השנה.

ביטול קטגוריה מסיר את נתוניה מהמטמון הפעיל ומהקובץ **לפני ההתחברות**, גם אם הרענון נכשל, ומשבית את הישויות תוך שמירת מזהים והיסטוריה. השבתת ישות ב־HA אינה עוצרת את שליפת הקטגוריה. בחירה ריקה שומרת הזדהות ורשימת תלמידים. [דוגמאות פעולות](docs/services.md#mashovset_options)

### תיבת דואר — לבחירה

**Mailbox — headers and unread count** יוצר חיישן אחד לכל חשבון ומוסד. כותרות אינן מסמנות שיחות כנקראו. **תוכן מלא כבוי כברירת מחדל; הפעלתו מסמנת את השיחות שנשלפו כנקראו במשו״ב**, גם בלי שפתחתם אותן. גופי ההודעות נשלפים כטקסט בלבד, ללא תמונות וקבצים מצורפים. ביטול תיבת הדואר מאפס הסכמה לתוכן מלא; הפעלה חוזרת מתחילה בכותרות בלבד.

המגבלה היא 20 שיחות אחרונות כברירת מחדל, בטווח 1–50. דואר שנשלח, טיוטות, ארכיון ודפים ישנים אינם נשלפים. תוכן ארוך יכול להתקצר במאפייני החיישן; בדקו `stored_conversations`, `fetched_conversations`, `body_truncated` ו־`content_status`. כשל בספירה אינו מוצג כאפס. ראו פרטיות וגישה לפני הפעלה.

### ישויות לכל תלמיד

כל סוג מידע שנבחר יוצר את החיישן המתאים לתלמיד. המצב הוא מספר רשומות, `unknown` למקור לא זמין ו־`0` לתשובה תקינה וריקה. מצאו מזהים בפועל במסך **ישויות**; בשדרוג נשמרים המזהים וההיסטוריה.

`items` מכיל רשומות; `formatted_summary`, `formatted_by_date` ו־`formatted_by_subject` מסייעים לתצוגה היכן שנתמכים. `total_items` ו־`stored_items` מציגים כמה רשומות זמינות וכמה נכנסו למאפיינים. `last_update`, `data_stale` ו־`source_status` מציגים עדכון בפועל, מידע ישן וזמינות מקור. `schedule_type` ו־`schedule_scope` מציגים תזמון וסוג ירושה.

תכנון שבועי משלים מקצועות ומורים מהמערכת ושומר הפרדה בין שבועות. שינוי שם או כיתה אינו מחליף נתוני תלמידים. [תמונות של כרטיסי המידע](examples/lovelace/README.md#picture-examples)

#### ישויות של המוסד והחשבון

בחירת חופשות יוצרת חיישן ולוח שנה לכל hub. השתמשו בישויות החופשות של המוסד המתאים בכרטיסים ובאוטומציות. תיבת הדואר היא ישות משותפת לחשבון, ולא חיישן נפרד לכל תלמיד.

## רשימות שיעורי בית וחיבור לבוטים

לכל ילד רשימת שיעורי בית מובנית ב־HA, עם סימוני ביצוע שנשמרים מקומית אחרי
רענון והפעלה מחדש. הסימונים אינם נשלחים למשחב.

חיבור MCP אופציונלי לקריאה בלבד מאפשר לבוט AI לענות למשל ״מה שיעורי הבית של כל
ילד?״ או לסכם ציונים, התנהגות והודעות. מפעילים את החשיפה בנפרד לכל האב ובוחרים
רק את ממשקי Mashov בהגדרות שרת ה־MCP של HA. בלקוח תומך בוחרים Streamable HTTP,
מזינים `https://YOUR_HA_HOST/api/mcp` ומתחברים כמנהל HA באמצעות OAuth.
בוט ללא תמיכה מובנית ב־MCP דורש מתאם; Telegram ו־WhatsApp הם ערוצי הודעות ואינם
לקוחות MCP בפני עצמם. [הגדרה ודוגמאות לבוטים](docs/homework-and-mcp.md).

## פתרון תקלות

- **אין חיישנים:** בדקו שנבחרו קטגוריות ב־Configure. אין צורך להוסיף חיישנים ידנית.
- **שגיאת הזדהות / 401:** בדקו פרטי כניסה ומוסד ועדכנו דרך Configure.
- **מקור חסום / 403:** ייתכן שהמוסד אינו מאפשר את המידע. האינטגרציה משהה ניסיונות חוזרים; אין להסיק מכך שהסיסמה שגויה.
- **מידע לא עדכני:** בדקו את `last_update` ואת `data_stale`, ונסו רענון ידני. מטמון עשוי להישאר כשמשו״ב אינו זמין.
- **מוסד אינו ברשימה:** חפשו לפי שם או סמל מוסד; אם הרשימה אינה נטענת, השתמשו בשדה הטקסט החלופי.
- **תלמיד שעזב:** לאחר רענון, אפשר למחוק מכשיר של תלמיד שאינו ברשימת החשבון. מחיקת כרטיס בדשבורד אינה מוחקת מכשיר או היסטוריה.

תקלות התחברות ורענון מוצגות בהתראה ב־HA. קישור לדיווח GitHub מוצע עבור שגיאות פנימיות ומצריך בדיקה ושליחה שלכם; דבר אינו נשלח אוטומטית. סשן שנסגר בזמן שליפת דואר מטופל ככשל שליפה תפעולי; שגיאות פנימיות אחרות נשארות ניתנות לדיווח.

להפעלת לוג מפורט:

```yaml
logger:
  logs:
    custom_components.mashov: debug
```

לפני שיתוף לוגים, צילומים או דיאגנוסטיקה, הסירו פרטי כניסה, מזהים, שמות תלמידים, ציונים, תוכן הודעות, עוגיות וטוקנים. אל תשתפו את קובץ `.storage/mashov.<entry_id>.cache`: הוא מכיל נתונים והזדהות. דיאגנוסטיקה כוללת מצבים וספירות טכניות ללא תוכן דואר.

## פרטיות ואבטחה

פרטי כניסה נשמרים ב־Home Assistant. מטמון נתוני בית הספר והסשן נמצא גם ב־`.storage/mashov.<entry_id>.cache`; אין לשתף קובץ זה. בדקו והסירו מידע אישי לפני שיתוף לוגים ודיאגנוסטיקה.

**כל משתמש HA, כולל ילד שאינו מנהל, יכול לקרוא את מאפייני חיישן הדואר.** הסתרת כרטיס אינה הרשאת גישה לישויות. הפעילו דואר רק אם המידע מתאים לכל המשתמשים.

`items` של הדואר מוחרג מרישום עתידי ב־Recorder; היסטוריה קיימת נשארת. המטמון שומר את התמונה האחרונה ללא מחיקה לפי גיל, וכשל יכול להשאיר מידע ישן מסומן. ביטול תוכן מלא מסיר גופים מהמטמון; ביטול תיבת הדואר מסיר גם כותרות ומאפס הסכמה. מחיקת hub מוחקת את המטמון והסשן שלו, אך לא היסטוריה או גיבויים.

אפשר להחריג גם את החיישן כולו: שלבו `recorder.exclude.entities` עם מזהה חיישן הדואר ב־`configuration.yaml` והפעילו מחדש. זו אינה מגבלת גישה ואינה מוחקת נתונים קודמים. דיווח על שגיאה פנימית נפתח לבדיקה שלכם; דבר אינו נשלח אוטומטית.
